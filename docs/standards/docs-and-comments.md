# Docs and comments standards

How to write prose that stays true: code comments, standards files, ADRs, skills, agents, plans and commit or PR bodies. A retro over the 237 review-fix commits on `develop` from 2026-08-01 to 2026-10-30 found prose that had gone stale, or was wrong from the start, to be the largest group of findings, about 80 commits. CLAUDE.md's self-check (search for stale references, re-read edited ranges, recount numbers) catches these after they are written. These rules keep them from being written.

- **Name the thing; don't count it or say where it sits.** A count or a position is true on the day it is typed, and nothing fails when the code moves. `devtools-paths.ts` said its module had "thirteen importers" when it had thirty (`f1c6ace`). ADR-0018 put a function's one caller "twelve lines down" when it sat twenty-three lines below the function's end (`870c57d`). `testing-api.md` pointed at the send-email bullet as "two bullets down" when it sat above (`7e33b2e`). So write "the shared-stub bullet", "`answerCase`'s one production caller", "every importer". Keep a number only when the number is the point, and then:
  - a measurement keeps its date, its machine and how many runs it averages, the way the git hooks' measured costs do;
  - a count that a reader can get from `git grep` or the project map is left out.
- **"Every", "only", "never", "all" and "nothing else" either name what enforces them or get narrowed.** An absolute claim is a promise about every future edit. When a check holds it, say which check, as the standards files do with `apps/web/dev/standards-guard.test.ts`. When none does, say what is true today and name the exception.
  - `usage-protocol.ts` called `hasRecordedSpend` "the only place" its rule was stated, while `scripts/issue-tokens.ts` stated it again. It now says "the one place the page states it" and names the terminal's copy (`52fc894`).
  - `testing-api.md` stopped saying all eight `mock.module` registrations had been replaced, because two had only shrunk to guards (`7e33b2e`).
- **Point to the ADR; don't retell its argument.** A comment or a standards bullet that summarises an ADR is a second copy of the argument, and the copies drift the way [conventions.md](conventions.md)'s one-owner rule describes for code. `870c57d` cut the same retelling out of three source files (`runner.ts`, `classify-case.ts` and `provider.ts`): "The ADR owns the argument; the comments point at it." Write what the code does, and add `(ADR-00NN)` for why.
- **A quotation is the source's exact words, or it is not in quotation marks.** A paraphrase in quotes misleads the next reader into searching for words that are not there. Describe it without quotes, or copy it exactly. The retro's own PR shipped one and its review sent it back (`2ac10bf`).
